# Contract: Server Actions (`app/actions/sinking-fund.ts`)

Each action is thin: authorize, parse with zod (`lib/validation/sinking-fund.ts`, amounts through
`parsePositiveCentavos`), call exactly one SQL function, `revalidatePath("/sinking-fund")` (and
`/dashboard` is **not** touched), return `ActionResult` via `run(...)`. Demo mode throws
`DEMO_MODE` before any write. Errors from SQL map through `lib/sinking-fund/messages.ts`; the message text
comes from the function for `P0001`.

| Action | Guard | SQL function | Success toast |
|---|---|---|---|
| `addParticipant` | `requireApprovedSession` | `sf_add_participant` | "Participant added" |
| `renameParticipant` | approved | `sf_rename_participant` | "Name updated" (unlinks the driver when linked) |
| `archiveParticipant` | `requirePermission("manage_fund")` | `sf_archive_participant` | "Participant archived" |
| `recordDeposit` | approved | `sf_record_deposit` | "Deposit recorded" |
| `recordLoan` | approved | `sf_record_loan` | "Loan recorded. To pay ₱2,100 by Dec 3" |
| `recordPayment` | approved (interest part honored only for owner by the function; the action also drops it for staff) | `sf_record_payment` | "Payment recorded. Balance ₱1,600" or "Payment recorded. Loan fully paid" |
| `recordSavingsWithdrawal` | `manage_fund` | `sf_record_savings_withdrawal` | "Savings withdrawal recorded" |
| `markLoanWithdrawal` | `manage_fund` | `sf_mark_loan_withdrawal` | "Loan closed as withdrawal. Savings unchanged." |
| `changeInterestPart` | `manage_fund` | `sf_change_interest_part` | "Interest part updated" |
| `distributeInterest` | `manage_fund` | `sf_distribute_interest` | "₱X distributed to N participants. Shares added to their savings." |
| `voidTransaction` | `manage_fund` | `sf_void_transaction` | "Transaction voided" |
| `voidDistribution` | `manage_fund` | `sf_void_distribution` | "Distribution voided" |
| `saveFundSettings` | `manage_fund` | `sf_set_default_prefill` | "Fund settings saved." |
| `loadParticipantHistory` (read) | approved | `sf_ledger_v` query | none; backs the detail sheet when the URL is opened client-side |

## Inputs (zod)

- Shared: `participantId` uuid; `date` `YYYY-MM-DD`, not after fleet today; `amountCentavos` positive
  integer; `notes` max 500; `idempotencyKey` uuid generated by the form when it opens.
- Loan: `amountCentavos % 10000 === 0` ("Loans must be in steps of ₱100 (₱100, ₱200, ₱300...).").
- Payment: `loanId` uuid; `interestPartCentavos` optional integer `>= 0`.
- `expectedUpdatedAt` on updates, voids, archive, rename, withdrawal, interest-part change.
- Void: `reason` 3–300 characters, trimmed.
- Distribute: `participantIds` uuid array, at least 1.

Client-side zod and `ledger.ts` give the same inline errors before submit; the server result is the
authority and its message replaces any mismatch.

## Error mapping (field errors where possible)

| Condition | Field | Message source |
|---|---|---|
| Duplicate name | `name` | "A participant named [name] already exists." |
| Loan not a ₱100 step / above savings | `amountCentavos` | the two exact messages in spec §6, or the date-aware SQL message |
| Payment above balance | `amountCentavos` | "Payment cannot be higher than the balance (₱X)." |
| Interest part out of range | `interestPartCentavos` | "Interest part must be between ₱X and ₱Y for this payment." |
| Savings or fund negative on a date | form-level | SQL message naming the date and available amount |
| Stale record | form-level | `STALE_RECORD` copy used by other pages |
| Non-owner on owner action | form-level | "Only the owner can do this." |
